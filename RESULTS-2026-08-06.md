## Task 1 — block-conditional truth after vectorised training

**Seed 0, 20k steps x batch 256, nfe 32, 500 traces.**

| | well-formed | true |
|---|---|---|
| naive-trained (M4 baseline) | 85.3% | **6.6%** |
| **vectorised** | **95.0%** | **29.4%** |
| unconditional single-block | 95.0% | 38.6% |
| noise floor | 82.6% | 6.7% |

Truth goes from *at the floor* to 4.4x the floor. The naive training algorithm
was the dominant term in the M4 failure.

### Per block — not flat

| block | well-formed | true |
|---|---|---|
| 0 | 99.2% | **61.0%** |
| 1 | 99.4% | 47.6% |
| 2 | 96.2% | 29.2% |
| 3 | 96.8% | 34.0% |
| 4 | 93.8% | 19.8% |
| 5 | 91.0% | 8.6% |
| 6 | 88.4% | **5.6%** |

This is the third shape: **decent early, collapsing at b5-b6**. An 11x spread
across block index. So the B=5 data-starvation diagnostic is triggered.

**Two things worth flagging immediately.**

1. **b0 (61.0%) and b1 (47.6%) BEAT the pooled unconditional model (38.6%).**
   b0 is the unconditional task — no prefix — so it should be the unconditional
   model's equal, not its superior. The likely reason is that the unconditional
   model pools every block position into one distribution, and block 0 steps do
   not look like block 5 steps; pooling heterogeneous positions makes the target
   harder, not easier. If so, 38.6% was itself a depressed reference and the real
   comparison is per-position.

2. The per-block **gate** losses after vectorisation are flat (b1-b6 all
   0.56-0.82%) while per-block **truth** spans 5.6-61.0%. That is the third
   independent instance in this project of regression loss and sample quality
   moving differently, and the first where they disagree about *which blocks are
   fine*.

## Task 2 — re-measure, retire, or keep

All measured on the vectorised seed-0 model, nfe 32, against the same numbers
taken on the naive-trained model.

### Retired — these were symptoms of undertraining

| diagnostic | naive-trained | vectorised | verdict |
|---|---|---|---|
| live-dim variance ratio (gen/real) | 0.831 | **0.992** | gone |
| total variance ratio | 0.837 | **1.000** | gone |
| shell under-norm at t=0 (nfe 50) | -7.8% | — (variance now exact) | gone |

The sampler now reproduces the marginal's second moment essentially exactly.
Both of these were load-bearing in my "the flow cannot hit the target" story and
neither survives. The 1b ablation had already shown the shrinkage was not causal
— decoder truth at the measured 0.912 amplitude was 95.8% against 97.5% — so
this is the second, independent reason to drop it.

Dead-dim ratio moved the other way (1.628 -> 3.887, and +279% relative deviation
at t=0), but the absolute variance there is ~0.0003 against ~1.0 in live dims,
and the 1b ablation showed the decoder ignores those directions entirely: noise
at sd 2.0, four orders of magnitude above what the sampler puts there, left truth
at 97.5%. Noise, not signal.

### Survives — properties of the data or the VAE, not the denoiser

| diagnostic | value | why it is unaffected |
|---|---|---|
| latent clustering, NN/mean | **0.280 vs 0.744 null** (ratio 0.377) | property of the frozen VAE |
| prefix explains 2-7% of next-block variance | unchanged | property of the data |
| unconditional 38.6% | unchanged | had no per-position split to starve |
| shift 1.5 > shift 0.5 by 8pp | unchanged | measured unconditionally |

Re-measured clustering directly and it is bit-identical, as expected.

### Survives but weakened — the trajectory departure

| | naive-trained | vectorised |
|---|---|---|
| departure begins | t = 0.500 | **t = 0.375** |
| max live-dim deviation | 22.6% | **13.2%** |

Still real, still in the mid-to-low-t region where the field has to encode
multimodality, but 40% smaller and starting later. This is now the strongest
surviving structural evidence, and it is genuinely stronger than before *as
evidence* — it was previously confounded with undertraining and no longer is.

### Re-measured: the loss gap — and one "survivor" does NOT survive

Naive-trained vs vectorised, averaged over t:

| block | A (naive) | A (vec) | info (naive) | **info (vec)** | shift (vec) | manifold (vec) |
|---|---|---|---|---|---|---|
| 1 | 0.700 | 0.516 | +0.044 | **+0.204** | -0.004 | +0.017 |
| 2 | 0.722 | 0.472 | +0.112 | **+0.600** | +0.005 | -0.004 |
| 4 | 0.762 | 0.527 | +0.118 | **+0.721** | -0.111 | -0.042 |
| 5 | 0.765 | 0.443 | +0.146 | **+1.298** | -0.219 | -0.028 |
| 6 | 0.826 | 0.488 | +0.163 | **+1.415** | -0.080 | -0.044 |

`info` = cost of swapping the true prefix for another trace's. `shift` = further
cost of using the sampler's generated prefix instead. `manifold` = the sampler's
own output scored as data.

**Three readings, and the first overturns something I listed as surviving.**

1. **"The prefix explains only 2-7% of next-block variance" does NOT survive.**
   Destroying the prefix now costs up to +1.42 against a base loss of 0.49 — a
   4x increase at b6. A signal worth 2-7% of the variance cannot do that. The
   2-7% came from a kNN estimate of Var(z0_b | prefix) in a 64-dimensional prefix
   space, where kNN systematically *under*-estimates predictability, so it was a
   floor artifact of the estimator rather than a fact about the data. The
   naive-trained model genuinely did not use the prefix much (info +0.04 to
   +0.16); the vectorised one uses it heavily. I read an estimator's weakness as
   a property of the problem, and it was the single load-bearing claim behind
   "there is nothing to condition on".

2. **`manifold` has gone to zero** (was -0.07 to -0.17, now -0.04 to +0.02). The
   sampler's own output is now exactly as hard to denoise as real data, i.e. it
   is on the manifold. Consistent with the variance ratio hitting 1.000.

3. **Exposure bias as *distribution shift* still does not exist** — `shift` is
   ~0 or negative at every block. But `info` rises monotonically with block
   index, from +0.20 at b1 to +1.42 at b6. So late blocks depend on their prefix
   FAR more than early ones, and at sampling time their prefix is generated
   content that is worth about as much as an unrelated trace's. That is exposure
   bias in the *informational* sense while being absent in the distributional
   one, and it tracks the per-block truth collapse (b0 61.0% -> b6 5.6%) closely.

This gives a second candidate explanation for the per-block collapse, competing
with data starvation. The B=5 diagnostic separates them: it equalises coverage
but leaves the dependence-on-prefix structure intact.

## Task 3 — decisions taken on a 6k-step naive gate

The naive gate needs ~30k steps to clear 2%; at 6k it reads 2.07-2.82% and
fails. The 1.20% reported at M3 was a 30k run, compared against 6k runs
afterwards. So the gate itself was never unreliable — but anything decided from
a 6k naive pass rested on an under-converged model.

| decision | rests on | status |
|---|---|---|
| M3 gate PASS licensing M4 | the 30k run (1.14% reproduced today) | **sound** — it was the converged one |
| M4 acceptance retirement | sampling, not the gate | unaffected |
| nfe/schedule sweep (truth flat 8-100) | naive-trained 40k x batch 8 model | **re-run needed** — measured on an undertrained model |
| loss-gap decomposition (M4) | same model | **re-measured** this session; conclusions changed |
| per-dim variance / shell under-norm | same model | **re-measured**; both retired |
| "underfit ruled out, held/train 1.01x" | same model | held, but it only ever excluded an *overfitting* gap |
| D=16 bottleneck choice | VAE only, no denoiser | unaffected |
| M2 gates, clustering, NN-rank | VAE only | unaffected |
| unconditional 38.6%, shift 1.5 vs 0.5 | no per-position split | unaffected |

The one item still owed is the **nfe/schedule sweep**, which concluded
"integration error is exonerated" from a model that could not use its prefix.
Worth redoing on the vectorised model before that conclusion is relied on.
